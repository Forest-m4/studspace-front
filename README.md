# StudSpace Front

Фронтенд VK Mini App StudSpace: бронирование студенческих залов и просмотр мероприятий.
Бэкенд: [kr0uch/studspace](https://github.com/kr0uch/studspace).

Стек: React, TypeScript, Vite, TailwindCSS, React Router, Feature-Sliced Design, VK Bridge, openapi-fetch, Docker, nginx.

## Запуск

```bash
npm install
npm run dev
```

Запросы на `/api/v1` в dev идут через прокси Vite, потому что CORS на бэке нет.
Адрес бэка по умолчанию лежит в `.env`, свой можно задать в `.env.local`.

## Настройки

| Переменная | Где | Зачем |
|---|---|---|
| `VITE_API_BASE_URL` | `.env` | базовый путь API |
| `VITE_API_PROXY_TARGET` | `.env` | куда dev-сервер проксирует API |
| `VITE_DEV_LAUNCH_PARAMS` | `.env.local` | подписанные launch params для работы вне VK |
| `VK_APP_SECRET` | `.env.local` | секрет приложения для `sign:params`, в сборку не попадает |

## Работа вне VK

Бэк принимает только подписанные launch params, и подпись живёт 24 часа.

1. Добавь в `.env.local` значение `VK_APP_SECRET`: тот же секрет, что `vk.app_secret` на бэке.
2. Получи параметры:

   ```bash
   npm run sign:params -- 1
   ```

   `1` здесь — `vk_user_id`.
3. Запиши результат в `.env.local` как `VITE_DEV_LAUNCH_PARAMS` и перезапусти `npm run dev`.

## Типы API

Типы в `src/shared/api/schema.d.ts` генерируются из Swagger бэка. Генератор использует `../studspace/docs/swagger.json`, если клон лежит рядом, иначе — сохранённый `docs/backend-swagger.json`. Можно передать путь явно: `npm run gen:api -- путь/к/swagger.json`.

```bash
npm run gen:api
```

Снимок Swagger соответствует коммиту бэка `33cd9321e930b2bfe2eb75af24935e2c205d0b57`. Swagger 2.0 сначала конвертируется в OpenAPI 3; генератор дополняет обязательность полей создания и переноса по серверной валидации.

## Запросы

```ts
import { api } from '@/shared/api'

const { data, error } = await api.GET('/me')
```

Заголовок `Authorization` клиент добавляет сам. Любой неуспешный HTTP-ответ превращается в `ApiRequestError` со статусом, кодом и ошибками полей. Ошибки сети также отображаются в интерфейсе.

## Подключённые сценарии

- В VK перед открытием страниц выполняются инициализация Bridge, синхронизация VK-профиля и загрузка `/me`. Вне VK нужен уже существующий на бэке пользователь и подписанные dev-параметры.
- Главная, помещения, расписание и календарь получают данные с API. Пустые списки и ошибки отображаются отдельно; доступен повторный запрос.
- Новая заявка отправляет имя и фамилию заявителя, название, цель, число участников, помещение и время с часовым поясом Москвы. Имя и фамилия заполняются из профиля и редактируются только для этой заявки; при повторном бронировании берутся из исходной заявки. Каждое поле обязательно, от 1 до 100 символов. Профиль VK не изменяется. При переносе имя сохраняется из исходной заявки. Проверяются вместимость, рабочие часы, шаг слота и занятость. Ответ сервера остаётся окончательной проверкой конфликта.
- Личные заявки поддерживают пагинацию и разрешённые сервером действия: отзыв, отмену, перенос и повторное бронирование. Перенос создаёт заявку на согласование; исходная бронь сохраняется до решения администратора.
- Администратор видит заявки по вкладкам, конфликты, счётчик новых и может одобрить, отклонить, отменить или вернуть заявку на рассмотрение.
- В карточках администратора название мероприятия и цель показаны отдельно. В расписании заявки на рассмотрении жёлтые, подтверждённые — зелёные; цвет зависит от статуса, а не от автора или помещения. Для статусов есть текстовые подписи и легенда.
- В профиле редактируются отчество и род занятий. Имя и фамилия берутся из VK. При уходе с несохранёнными изменениями появляется подтверждение.
- «Мероприятия» показывает одобренные бронирования через `GET /bookings?from=&to=`. Отдельных мероприятий, регистрации участников и листа ожидания в текущем API нет.
- Нажатие на запись в расписании, карточку мероприятия или событие дня открывает сведения выбранной заявки: название, статус, помещение, время, заявитель, цель и число участников. Для расписания подробности загружаются из существующих списков своих заявок, заявок администратора или одобренных бронирований. У чужой заявки на рассмотрении API предоставляет только краткие данные расписания; интерфейс сообщает об этом. При ошибке загрузки можно повторить запрос.

Даты и время отображаются в `Europe/Moscow`. Интерфейс сверен с Figma «Соц проект (Copy)».

Поля имени и фамилии редактируются на фронте и передаются как `first_name` и `last_name` в `POST /bookings`. В текущем опубликованном контракте API их ещё нет: поддержка сохранения согласуется с командой бэка. До этого сервер может вернуть имя из профиля вместо введённого. Изменений серверного кода в этом репозитории нет.

## Проверки и локальное демо

```bash
npm run build
npm run lint
npm test
```

Для проверки интерфейса без работающего бэка есть отдельный тестовый сервер с вымышленными данными. Он не подключается автоматически и не попадает в production-сборку.

В первом терминале:

```bash
node tests/fixtures/api-server.mjs
```

Во втором (PowerShell):

```powershell
$env:VITE_API_PROXY_TARGET='http://127.0.0.1:18081'
npm run dev -- --host 127.0.0.1 --port 5173
```

Без этой переменной Vite использует настоящий бэк из `.env`. Для nginx контейнер фронта должен находиться в одной Docker-сети с `studspace_server`, либо нужно заменить upstream в `nginx.conf` на адрес своего бэка.
